# 独立助手沙箱

这是一项默认关闭的可选功能。未部署执行服务、未填写连接凭据或未打开开关时，助手仍可查询状态、管理非敏感配置及调用受支持的插件动作，不会在主系统运行代码。

## 当前提供方式

使用沙箱需要单独部署兼容的执行服务，系统不会自动创建它。目前没有提供一键安装方式；没有可用执行服务时，请保持此功能关闭，普通助手功能不受影响。

不要给主系统容器添加 Docker socket、宿主目录或特权来代替沙箱。

## 能做什么

已部署执行端后，助手可在当前会话的临时工作目录中运行 Python 或 Shell、列出和读写文件，或使用独立 Chromium 浏览器打开网页、查看内容、点击、填写、选择、执行网页脚本和截图。每次操作都显示具体内容，确认后才执行。

这些操作发生在沙箱，不是系统服务器。沙箱中没有现有插件、配置、Telegram Session、CookieCloud 数据或系统密钥。生成代码不等于已安装插件；修改沙箱文件也不等于修改系统源码。发布、安装或提交结果应以实际执行回执为准。

浏览器可保留本次沙箱会话的网页状态；请求只允许公网 HTTP(S)，不访问本机、内网、Docker 服务或云元数据地址。不支持 WebSocket、任意端口、附件下载或无限量资源加载。网页资料仍不可信，网页中的“确认”不能批准系统操作。

## 隔离与安全

主系统通过管理员设置的地址调用 broker，不安装 Docker SDK，也不挂载 Docker socket。broker 是独立的受信管理服务，由它创建执行容器。

每个会话使用单独容器。runner 使用非 root 用户、只读根目录、临时工作目录、资源和时长上限，没有系统目录或 Docker socket 挂载，也没有直接网络。网页资源由 broker 验证全部 DNS 地址后固定公网 IP 访问，并保留 HTTPS 域名证书验证。公网重定向仍须经过下一次地址验证。

正常完成后可在同一会话继续使用临时文件；空闲、停止、超时、连接配置变化或结果未知时会清理。不要把沙箱当作长期存储，也不要在其中填写系统密钥。取消不会撤销已经发送到外部网站的操作。

Docker 不是绝对安全边界。broker 的 Docker socket 等同高权限管理入口，只应部署到受信 Docker 主机；不要暴露到公网、不要转发给插件或模型。处理不可信代码时，建议把执行服务放在独立主机。

## 连接与维护

在「系统设置 → 系统助手 → 常规与渠道 → 独立沙箱」填写现有执行端的受保护地址及专用令牌，保存后点击「检查连接」。保存只记录配置，不表示已连接成功。远程连接使用 HTTPS，不要直接把执行端端口暴露到公网。还需开启助手的「允许执行修改操作」，每次操作仍须确认。

维护或停用前先停止正在执行的助手任务，再关闭独立沙箱开关。使用原部署文件停止 broker。升级须保留并核对配套镜像、部署文件和令牌；临时工作目录不保证跨重建保留，助手会话及配置仍保存在系统的数据目录。

执行失败或结果不确定时，不要反复批准同一个外部写操作，先核对网站实际结果。连接错误只返回简短原因，不把上游响应、连接凭据或 Docker 错误全文交给模型。

Docker 创建容器的结果不确定时，该会话会被隔离并继续占用执行名额，避免重试不断创建容器。先恢复 Docker，再用原令牌启动 broker 清理遗留执行容器。若清理失败，执行服务不会继续接收操作，不要通过反复修改令牌绕过隔离状态。

更换连接令牌前，先停止 broker，并确认旧执行容器已经回收，再替换令牌文件和系统设置，最后启动 broker。专属标签与令牌相关；更换令牌后不会自动清理旧令牌所属的容器。若 Docker 故障导致清理未完成，先保留原令牌恢复和清理，不要直接换令牌重建。
