# 授权升级说明

本页适用于已有安装的授权升级，以及需要使用 Pro 的 Docker 部署。

**长期授权权益不变，不改成按天订阅。** 系统在启动后和运行中需要联网验证；未完成验证或有效验证凭证失效时，非内置插件暂不可用，但不等于授权被取消。请保持服务器时间正确、授权服务可访问，不要靠删除授权数据或重装处理验证失败。

## 先做这三件事

1. **先确认授权服务已完成对应升级，再更新平台。** 授权服务由管理员维护，普通用户不需要自行部署；使用自建授权服务时，请先向维护者确认。
2. **备份原来的完整数据和部署配置。** 包括 `data`、`sessions`、`plugins`、Compose 文件，以及实际使用的 `.env`、覆盖文件和额外挂载目录。重要更新前短暂停止系统再备份，备份使用新文件名，不覆盖上次备份。
3. **保留同一套安装。** 在原部署目录更新，保留原数据挂载、Compose 服务名（如 `awbotnest`）、`container_name`、网络和端口。不要另建空数据目录，也不要让两套实例同时使用同一授权或 Telegram 会话。

## 一键安装用户

重新执行原来的一键命令，选择**原来的安装目录、网络模式和端口**：

```bash
curl -fsSL https://raw.githubusercontent.com/AWdress/AWBotHub/main/install.sh | sudo bash
```

请在**运行本机 Linux Docker 服务的主机**执行，不要在容器终端内执行。一键脚本只支持本机标准 Docker 套接字；远程 Docker context、`DOCKER_HOST`、Docker Desktop 或特殊套接字请使用原来的 Compose 部署方式。该限制只针对一键脚本，不表示 Docker Desktop 或未额外挂载主机标识的安装不能使用 Pro。

普通 Docker 安装无需手动增加授权挂载。系统会把授权所需的安装信息保存到原 `data`；升级时完整保留即可。若原部署已有主机标识挂载或运行覆盖文件，继续使用原配置，不要删掉或更换。

## Compose 用户：保留原配置，直接更新镜像

无需为了授权增加挂载、改容器名或重新创建安装。进入**原来的部署目录**，沿用原 Compose 文件及完整的覆盖文件列表。镜像使用 `awdress/awbothub:latest`；需要固定版本时选择已发布的正式标签。

```bash
cd /opt/AWBotNest &&
docker compose config -q &&
docker compose pull awbotnest &&
docker compose up -d awbotnest
```

示例中的 `awbotnest` 是 Compose 服务名，不是容器名。目录和服务名按原部署替换；原数据使用其他绝对路径或命名卷时，也必须保留原挂载，不要改成示例路径。

上一步失败时，后面的更新命令不会继续执行；先处理错误，不要删除数据或另建实例。这里只重建原服务，已有完整数据会继续使用，不需要执行删除卷命令。

如果原部署使用 `docker-compose.awbotnest-runtime.yml`，上面三条命令都要带上同样的文件列表，例如：

```bash
docker compose -f docker-compose.yml -f docker-compose.awbotnest-runtime.yml config -q &&
docker compose -f docker-compose.yml -f docker-compose.awbotnest-runtime.yml pull awbotnest &&
docker compose -f docker-compose.yml -f docker-compose.awbotnest-runtime.yml up -d awbotnest
```

其他自定义覆盖文件同理，使用原来完整的 `-f` 列表，不要遗漏。**已经配置主机标识挂载的安装，继续保留原挂载和源文件**；无需新增不代表可以删除原来的绑定。

## 更新后检查

打开网页，进入“系统设置 → 账号与凭据 → 系统授权”，等待自动联网验证。保留原完整 `data` 且原授权有效时，会自动继续使用，不需要重新填写激活码。随后检查已有插件的启用状态和日志。

网络暂时中断后，系统会自动重试；连接恢复并验证成功后，只恢复原本启用的插件，不重新打开手动停用的插件。已经因验证失败跳过的历史定时任务不会全部补跑，需要时核对插件日志后手动运行一次。

首次安装或原来没有授权时，才需要填写自己的有效激活码。若已有授权没有自动恢复，按下面步骤排查，不要先删除授权信息或反复授权。

## 没有恢复 Pro 时怎么查

- **原数据未完整保留：** 检查是否仍挂载原来的整个 `data`，而不是只复制 `config.json`。核对容器实际使用的路径、目录权限及原来的覆盖文件；不要另建空目录或删除授权文件。
- **原有额外挂载不可用：** 只有原来已经使用主机标识绑定的安装，才需核对原挂载、源文件和同一主机是否仍可用。保留原配置；不要删除挂载、伪造文件或复制别台机器的标识。
- **时间或网络异常：** 校准服务器时间，检查系统能否访问授权服务，等待自动续验。不要回拨时间或反复删除安装信息。
- **提示绑定其他系统：** 核对是否误用了空数据目录或换了安装。换机前先停旧实例；已经使用主机绑定或需要转给另一套独立安装时，联系授权管理员按流程解绑。复制完整数据会一并复制安装身份，不等于取得另一份授权，不要同时运行两套实例。
- **提示授权正在另一运行实例使用：** 停止共用这套数据和授权的其他实例，等待系统自动重试。正常重启时也可能短暂等待，不需要清空授权信息或重新填写激活码。
- **已授权但插件同步失败：** 另查 GitHub 网络、限流和插件日志；下载失败不需要更换激活码。

请勿公开实际主机标识、激活码、授权凭证、配置包或完整数据目录。向维护者反馈时只提供脱敏提示、系统版本和部署方式。

## 关于回退

完成新版联网授权验证后，授权状态和服务协议已更新，**不能只改镜像标签退回旧客户端，也不能直接退回旧授权服务**。需要回退时，先停止相关实例，联系维护者制定平台、授权服务和相应一致备份的整体恢复方案；不要通过清空授权数据尝试降级。
